# 04. Telegram-чаты

Дата разведки: 2026-08-24. Источник: экспорт чата «❗️ЗАКАЗЫ/ОТМЕНЫ» из Telegram Desktop владельца (599 сообщений, 01.01–24.08.2026) — `recon/data/chat_orders_export.json` + папка photos в экспорте.

Чат выполненных заказов НЕ выгружался — решение владельца, поддержанное разведкой: его наполняет сам бот, источник истины — БД бота (уже выгружена и посчитана в M5).

## Состав чата «❗️ЗАКАЗЫ/ОТМЕНЫ»

- Тип: private_group, 3 участника. Авторы сообщений: «Саныч» — 513 (оператор, основной поток), «Ракета Химчистка» — 43 [предположение: аккаунт компании, транслирует заявки клиентского бота], «Евгений» — 43 (владелец).
- Темп: ~2,5 сообщения в день.
- **Структура: 236 (39%) — фото без текста, 226 (38%) — фото с подписью, 137 (23%) — только текст.** Фото — **скриншоты событий Google Calendar** (проверено просмотром: карточка события с заголовком «Лен! Стулья, Юлия», датой, адресом, описанием и телефоном). То есть чат для заказов — уведомительный слой поверх календаря и уникальных данных о заказе не несёт; уникальны только отмены/комментарии оператора.
- Пересланных алертов бота/амо («🚨 amoCRM: новая заявка», «⚠️ Оценка N по заказу», «📩 Заявка на заказ») — 29: чат используется и как рабочая лента, не только для заказов.

## Отмены и переносы

- 44 сообщения с «отмена/перенос/отбой/заболела». Формат свободный и короткий: «Отмена», «Перенос», «Перенос, заболела», «Пока отбой, позвонит выберем дату».
- **Только 5 из 44 сделаны реплаем на исходное сообщение** — в остальных случаях связь «какая именно отмена» восстанавливается только по контексту/времени. Для автоматики это слабый сигнал; надёжный сигнал отмены — удаление события в календаре (см. 02).

## Ковровый поток — как он устроен на самом деле (со слов владельца, 2026-08-24)

1. Клиент звонит → оператор принимает заказ, фиксирует его в заметку, делает скриншот заметки и кидает в этот чат (**иногда забывает**).
2. Оператор **звонит партнёру и диктует заказ по телефону** — партнёр забивает его в свою CRM. Чат в передаче заказа партнёру НЕ участвует.
3. Владелец заводит сделку в амо по скрину из чата (**если скрин забыт — сделка не заводится**).
4. Заказ выполняется, партнёр присылает Excel-отчёт.
5. Владелец находит сделку в амо и проводит в выполненную, **или не находит — и создаёт задним числом**.

Это объясняет провалы M7: «сделки нет» и «сделка не в ковровой воронке» — прямое следствие шага 1 («забыли скрин») и шага 3. Пример скрина заметки — `recon/data/carpet_chat_example.png`: «Вск с 18-21:00 / М. Шоссе д 167к2… / ФИО / +7 (910) …» — **дата днём недели без числа в скриншотах встречается** (в отличие от текстовых сообщений, см. M9).

## Ковровые заказы (текстовые сообщения)

- Текстовых ковровых сообщений-заказов (с телефоном или датой): 16 за 8 месяцев. Устойчивый шаблон: `[Район] / Ковры / дд.мм с ЧЧ-ЧЧ:00 / адрес / ФИО / телефон` — но с вариациями порядка строк.
- **M9 = 0/16**: дат «днём недели без числа» (пример из брифа «Вск с 18-21:00») не встретилось; день недели если есть — то вместе с числом («Пн 23.03», «Ср 15.07»). Опасение брифа на этих данных не подтверждается.
- Часть ковровых уходит фото с подписью («Слобода, Ксения ⏎ Ковры 15.08», «+ковры на 20.08»).

## M6: заказы партнёра ↔ чат

- Из 51 заказа партнёра (Excel) телефон находится в **текстах** чата лишь у 11 (22%). Обратно: из 13 ковровых текстов с телефоном в Excel нашлись 3.
- Причина расхождения: (а) заказы уходят скриншотами — телефон на картинке, текстовый матчинг слеп; (б) в сообщении от 15.07 упоминается «добавить в заявку из соседней группы в дс» — похоже, существует ещё один канал передачи ковровых заказов партнёру, не этот чат. **Это расходится с брифом («ковровые заказы попадают только в Telegram-чат») — открытый вопрос владельцу (07, п.17).**

## Бот в чатах

- В чате «❗️ЗАКАЗЫ/ОТМЕНЫ» бота компании нет среди авторов — он туда не пишет и, соответственно, историю не видит. Чаты, куда бот пишет: `ORDERS_CONFIRM_CHAT_ID` (чеки заказов), `MONEY_FLOW_CHAT_ID` (касса), `LOGS_CHAT_ID` и др. — см. 03-bot.md.
