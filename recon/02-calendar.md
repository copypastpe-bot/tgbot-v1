## Формат заголовка

`<Префикс>! <Услуга>, <Имя>` — устойчив: 320 из 339 заказов (94%) начинаются с «Префикс!».

Частоты префиксов: Ниж 79, Сов 75, Лен 27, Авт 22, Сорм 20, Кан 19, При 11, Кст 10, Бор 9, Приок 8, Мос 7, Печер 3, Моск 3, Сор 3, АП 3, единичные: Ксто, Печ, Коз, Ап, Цветы.

Расшифровка (подтверждено владельцем): районы Нижнего Новгорода и пригороды — Ниж=Нижегородский, Сов=Советский, Авт=Автозаводский, Сорм/Сор=Сормовский, Кан=Канавинский, Лен=Ленинский, Мос/Моск=Московский, При/Приок=Приокский, Печер/Печ=Печёры, Кст/Ксто=Кстово, Бор=Бор, АП/Ап=Анкудиновка; Коз — владелец не помнит [вероятно Козино]. Дублирующие написания одного района (Сорм/Сор, При/Приок, Мос/Моск, Кст/Ксто) — парсер должен приводить к канону.

Отклонения (19 шт., 6%): запятая вместо «!» («Сов, Уборка, Андрей»), без префикса («Ковролин Виктория»).

## Формат описания

Типовая структура (по строкам): позиции с ценами → опции («Сушка 40», «Нз 1800₽») → комментарии → телефон + имя. Адрес — в отдельном поле location (обычно «Улица, дом, кв, п(одъезд), эт(аж)», иногда код домофона).

Жаргон (расшифровки подтверждены владельцем 2026-08-24):
- «Сушка 40» — сушка 40 минут; «сушка/2» — на 2 стороны/предмета; «Без сушки»;
- «Нз» — нейтрализация запаха (цена отдельно: «Нз 1800₽», «Нз по месту решить»);
- «б/п» — без подушек;
- «Мин выезд 3000₽» — минимальная сумма выезда;
- «Матрас 160/1», «180/2» — размер / количество сторон чистки;
- «По фото» — оценка по фото; «подушки по 500» — цена за штуку.

## Телефоны (M4)

Посимвольный сканер (алгоритм как в bot.py) извлекает телефон из **334 из 339 (98,5%)** событий-заказов. Форматы разные: «89601861067», «+7 922 088‑82‑08» (с юникод-пробелами и неразрывными дефисами), «Ирина 89159496642» (nbsp). Простая регулярка вида `(?:\+7|8)…` справляется заметно хуже — вывод: парсер телефона должен быть посимвольным, как канон бота.

Провалы M4 (5 шт., 1,5%): «Авт! Стулья, Светлана» (B2B, 39 стульев, без телефона в тексте), «Авт! Перемыв, Светлана» (перемыв — телефона нет), «Авт! Уборка Анастасия», «Кан! Матрас, Татьяна», «Кан! Диван» (Наталья, «оплата безнал») — телефона просто нет в событии.

## Механика изменений

- **Отмена = удаление события** (подтверждено владельцем). В обычной выдаче API удалённые события НЕ видны; чтобы ловить отмены, интеграции нужен инкрементальный sync (syncToken + showDeleted → приходит `status: cancelled`) либо периодическое сравнение снапшотов. Проверить фактическое поведение syncToken в разведке нечем (MCP-доступ не даёт syncToken) — пометка для этапа проектирования. [ограничение]
- Правки задним числом: **60 из 339 заказов (18%) правились спустя >48 ч после создания** (updated ≫ created) — переносы дат, дописывание состава (пример из брифа «+ковры на 20.08» — такие есть).
- Таймзона событий почти всегда Europe/Moscow, но встречается Europe/Simferopol (создано с устройства с другой tz) — парсер дат должен читать tz события, а не предполагать московскую.

## Техническая готовность

- HTTPS-инфраструктура на VPS есть (nginx с валидным сертификатом обслуживает analytics.dastydev.ru) — поднять endpoint для `events.watch` технически возможно. [факт]
- `extendedProperties` в выгруженных событиях отсутствуют (никто не пишет). Запись в `extendedProperties.private` с текущей ролью «reader» невозможна — понадобится доступ «writer» или сервисный аккаунт, когда дойдёт до внедрения. [факт/ограничение]
