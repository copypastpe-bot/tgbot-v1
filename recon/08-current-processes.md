# 08. Текущие процессы — как есть

Источники: данные амо/БД за 90 дней, код бота, ответы владельца 2026-08-24. Помечено: [факт из данных] / [со слов владельца] / [предположение]. Разделы про чат и календарь будут дополнены после получения экспорта чатов и доступа к календарю.

## Полный жизненный цикл заказа (мебель/клининг)

1. **Заявка.** Звонок (OnlinePBX) или сообщение → сделка в первичной воронке создаётся автоматически, контакт цепляется по телефону, ответственный «Женя/Дима», робот сразу ставит задачу «1-ый звонок» (связаться за 15 минут) [факт: 275 таких задач/90 дн; примечания lead_auto_created 471, call_in 328].
2. **Продажа.** Оператор ведёт сделку по этапам первичной воронки. Успех = этап «Передано в работу» [факт: 276/90 дн], отказ = «Закрыто и не реализовано» [факт: 153/90 дн, причина — поле «Причина закрытия», заполнено в 21% всех сделок].
3. **Автосоздание сделки реализации.** Сейлзбот при «Передано в работу» создаёт сделку в воронке по услуге: мебель/клининг → «Воронка для реализации», ковры → «Ковры Кристал» [со слов владельца; подтверждено именами «Автосделка: Сделка #…»].
4. **Запись в календарь.** Заказ фиксируется событием в Google Calendar (видят мастера) [со слов владельца/бриф; детали — после доступа].
5. **Подтверждение.** В воронке реализации на этапе «Заказ оформлен» робот ставит задачу «ПРОВЕРЬ КАЛЕНДАРЬ!.. Назначь мастера и подтверди заказ!» (срок 0–72 ч) [факт: 188/90 дн]. Владелец сверяет с календарём, двигает сделку в «Заказ подтвержден, Мастер назначен» — РУЧНАЯ РАБОТА.
6. **Выполнение.** Робот ставит «Выполни заказ и получи оплату!» (+24 ч) [факт: 125/90 дн]. Мастер выполняет заказ.
7. **Проведение в боте.** Мастер жмёт «🧾 Заказ», вбивает телефон руками, бот считает чек/бонусы/З-П, пишет заказ в Postgres («Заказ №N» = id), шлёт чек в чат подтверждений и строку в чат денег, клиенту — сообщение с чеком и бонусами, через 24 ч — запрос оценки [факт: код, 171 заказ/90 дн ≈ 2/день].
8. **Проведение в амо.** Владелец читает сообщения бота и руками двигает сделку реализации в «ЗАКАЗ ВЫПОЛНЕН и Оплата получена» [факт: 229/90 дн] — РУЧНАЯ РАБОТА №2 из брифа.
9. **Обратная связь.** Бот собирает оценку 1–5 (ветвление: 5 → ссылка на отзовики, ≤3 → алерт владельцу). Робот в амо ставит задачу «Получить ОС…» (+24 ч) [факт: 185/90 дн] — текст задачи описывает старый процесс (бонусы 300, ДР), теперь это делает бот; владелец звонит сам только если клиент не ответил боту [со слов владельца]. Остаётся ручной по решению владельца.

## Отмена и перенос [со слов владельца]

- Запись удаляется из календаря + сообщение в чат «❗ЗАКАЗЫ/ОТМЕНЫ».
- Далее владелец руками в воронке реализации:
  - окончательная отмена → «Закрыто и не реализовано» + выбор причины;
  - перенос без новой даты → назад в «Заказ оформлен»; робот заново ставит «подтвердить и назначить мастера», владелец созванивается и передоговаривается.
- Комментарий «отменен» (из брифа) не пишется [факт: 0 таких примечаний за 90 дней].

## Ковровый контур (партнёр «Кристалл») [со слов владельца, 2026-08-24]

1. Клиент звонит → оператор фиксирует заказ в заметку, делает скриншот и кидает в чат «❗ЗАКАЗЫ/ОТМЕНЫ» (**иногда забывает**). В скриншотах заметок дата бывает «днём недели без числа» («Вск с 18-21:00»).
2. Оператор **звонит партнёру и диктует заказ** — партнёр забивает его в свою CRM. Двойной ручной ввод: у нас и у партнёра.
3. Владелец заводит сделку в амо по скрину из чата; **если скрин забыт — сделка не заводится** (источник провалов M7 «сделки нет»).
4. Партнёр выполняет (забор → цех → сдача, цикл 1–2 недели) и присылает Excel: недельный (иногда забывают) + месячный свод (всегда, все выполненные); отказы отдельным файлом.
5. Владелец находит сделку в амо и проводит в выполненную, **или создаёт задним числом, если её не было** — РУЧНАЯ РАБОТА №3 из брифа [факт: 54 доставленных/90 дн].

## Ручной перенос данных амо → бот

- Владелец выгружает CSV сделок из амо и скармливает боту команду `/import_amocrm` (dry-run превью → подтверждение) [факт: код bot.py:9632, пример файла — 41 сделка] — РУЧНАЯ РАБОТА №4 из брифа. Периодичность ~раз в неделю [бриф].
- Импорт обновляет клиентов/лидов по телефону; сделки одного клиента схлопываются в одну запись.

## Оценка объёма ручной работы (по данным)

| Операция | Объём |
|---|---|
| Утренний разбор чата «❗ЗАКАЗЫ/ОТМЕНЫ» → сделки в амо | ~2,5 сообщения/день (599 за 8 мес.), из них отмены/переносы 44 за 8 мес. (~1,4/нед); заказы в чате = скриншоты календаря |
| Проведение выполненных (мебель/клининг) | ~2,5 сделки/день (229/90 дн) |
| Подтверждение + назначение мастера | ~2 задачи/день (188/90 дн) |
| Ковровые сделки по Excel | ~13/нед в сезон высокой загрузки, в среднем 51/5 файлов |
| CSV-импорт амо → бот | ~1 раз/нед, ~40 сделок, плюс время на выгрузку из UI амо |
